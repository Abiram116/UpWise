# UpWise — Plans

Living backlog of things to build next. Nothing here is built yet — this is the roadmap, not a changelog. Grouped by theme, roughly in priority order within each group.

## 1. Bugs & core UX (do these first)

- [x] **Scroll position leaks across screens.** Caught live: scroll down on Home, tap an item, and the detail screen opened already scrolled down. `main.app-main` is the actual scroll container and persists across routes (only the `Outlet` child remounts), so its `scrollTop` carried over. Fixed: reset it to 0 on every pathname change.

- [x] **PIN screen: keyboard covers/scrolls half the screen.** Caught live on device. The invisible PIN `<input>` sat in normal document flow with `position: absolute`, so focusing it made the WebView auto-scroll it into view when the keyboard opened, dragging the whole centered layout up into a broken half-scrolled state. Fixed: input is `position: fixed` pinned at a static viewport corner (never needs scrolling into view), `overflow: hidden` on the screen, and the Activity now declares `android:windowSoftInputMode="adjustResize"` so the WebView's `100dvh` actually shrinks above the keyboard instead of the keyboard just overlaying it.

- [x] **Add-sheet gets stuck.** ~~It currently blocks closing while analyzing~~ Fixed: the sheet can be dismissed anytime now; the analyze call keeps running in the background (each attempt tracked by id) and reports via toast on completion instead of blocking the screen. Verified in the desktop build — dismiss mid-analysis unblocks the UI immediately, the item still lands in the library, reopening shows a clean form.
- [x] **Status bar invisible in light mode.** Done: `MainActivity.kt` exposes a JS bridge (`AndroidNative.setLightStatusBar`) that calls `WindowInsetsControllerCompat.isAppearanceLightStatusBars`; `theme.ts` calls it on init, on every theme change, and on OS-level light/dark switches while in "system" mode.
- [x] **App icon missing on both platforms.** Fixed: Android was building the icon into `src-tauri/icons/android/` but never syncing it into the actual build resources (`gen/android/.../res/mipmap-*`), and the adaptive-icon XML (`mipmap-anydpi-v26/ic_launcher.xml` + background color) was entirely missing — added both, confirmed on device. Windows icon confirmed correctly embedded after a full icon-cache clear.
- **Notification tray icon still generic.** Attempted fix via `tauri.conf.json`'s `plugins.notification.icon` config crashed the app at launch on Android (`tauri-plugin-notification`'s Rust config type is unit-only — any object value there panics on setup, on every platform, not just desktop where it was first caught). Reverted; tray icon falls back to the generic system icon for now. Needs a different approach — maybe a newer plugin version, or setting it purely via the Android resource naming convention if the plugin supports that without JSON config.
- [x] **Copy audit.** Checked all "add link" copy — already source-agnostic everywhere except the Home empty-state, which leaned YouTube-first; broadened to mention YouTube/Instagram/paste evenly.
- [x] **Android update install was a dead end.** Caught live — "Check for updates" opened the APK URL in Chrome, which downloaded it but left the user to hunt through Chrome's Downloads menu with no notification ever appearing. Fixed: `AndroidNative.downloadAndInstall` (new `MainActivity.kt` bridge method) uses the system `DownloadManager` directly — proper download notification, survives backgrounding, and a `BroadcastReceiver` on `ACTION_DOWNLOAD_COMPLETE` opens the installer automatically the moment it lands. Added `REQUEST_INSTALL_PACKAGES` so repeat updates need only one one-time permission grant. Verified: compiles and builds clean; real end-to-end install exercised on the next release.
- [x] **Article/link thumbnails missing more than they should.** Two fixes: (1) `fetchArticle` only ever grabbed `og:image` inside the "Jina failed" fallback branch — meaning *most* successfully-read articles never got a thumbnail at all, since Jina's markdown output has no structured place for images. Now fetches it as long as any of title/content/thumbnail is still missing, verified live (a Wikipedia page genuinely has no `og:image` — confirmed via curl, correctly stays blank; a FreeCodeCamp article now gets its real thumbnail). (2) For items that truly have no image, the fallback is no longer a flat gray box with a tiny icon — it's now tonal (sage for YouTube, apricot for Instagram/articles), matching the app's own Material palette instead of looking broken.
- [x] **GitHub Actions release pipeline was serial for no reason.** `android` job had `needs: windows` purely because `tauri-action` (in the windows job) was what created the GitHub Release, and android just uploaded to it after — a false dependency that made every release ~16 min (10+6 sequential) instead of ~10 min (parallel). Split release-creation into its own fast first job that both windows and android now depend on independently; they build in true parallel. Same single release at the end, just faster to get there.
- [x] **Cold-start loading flash on every open.** Caught live — a returning user saw a full-screen spinner for ~a second on every launch while `profile` (a real network fetch) resolved, purely to decide "onboarded or not." Fixed: the onboarded flag is now also cached in `localStorage` (synchronous, read on first render, no async wait) — once a user has onboarded once, every later launch renders the app shell immediately instead of blocking on the network. Profile data itself still arrives normally in the background; Home/Settings already null-safe that. Only a genuinely first-ever launch still waits on the real fetch, since there's nothing to fall back to yet.

## 2. Content reliability

- [x] **Instagram Reels — actually fixable.** Done: `fetchInstagram` now also pulls `og:video`/`og:video:secure_url` when Instagram exposes it on the public page; if present, the edge function downloads the file (capped ~20MB) and sends it straight to Groq Whisper (`whisper-large-v3-turbo`) — Whisper decodes audio out of the mp4 itself, no ffmpeg needed. Real transcript, not a title guess, whenever Instagram exposes the video URL. Honest caveat: Instagram doesn't always expose `og:video` (anti-scraping, varies by reel) — when it doesn't, this silently falls back to the existing title/description approach exactly as before, same as the carousel-post limitation below. Deployed and smoke-tested (no crash on a reel with no exposed video URL); a real end-to-end transcription will get exercised the next time a reel that does expose one gets saved.
- **Instagram carousel posts — capped by no-login access.** Can't read slide 2+ without Instagram auth (out of scope). Instead: detect it's a carousel, prompt harder for a note, stop pretending confidence.
- [x] **Articles — fallback chain.** Done: Jina Reader first, then a direct fetch with actual readability-style extraction (strips script/nav/chrome tags, prefers `<article>`/`<main>`, keeps real paragraph text) if Jina came back thin, then explicit `pdf_unsupported`/`unreadable` status if neither worked — visible on the item as `transcript_status` and reflected honestly in the AI prompt ("NO TRANSCRIPT/CONTENT AVAILABLE") instead of a silent thin guess. Deployed to `analyze-link` and verified live against a real Wikipedia article (`jina_ok`) and a PDF (also read cleanly by Jina).
- [x] **"Limited info" trust badge.** Done: `has_transcript` now also covers extracted article text (was silently false for every article before), and a new `confidence()` helper shows "Limited info" / "AI unavailable" on the item row and detail page whenever analysis worked from just a title. Verified against real seeded items — badge appears exactly where it should.

## 3. Performance

- [x] **Android (Tensor G3): the concrete wins.** Found by code review (no device attached to profile live, so this is what's verifiable without one): `refetchOnWindowFocus` disabled globally — every app-switch was refetching all active queries the instant the user looked back at the screen, the worst possible moment for jank. The one real `backdrop-filter: blur()` in the app (play-button badge on the detail page) swapped for a plain darker `rgba` fill — visually identical on a small circular badge, no compositing-layer cost. Found a genuine bug along the way: `SessionBar`'s elapsed-time timer (`setInterval`, 1s) had an empty dependency array, so it ticked forever for the entire time the app was open — even with zero active learning sessions. Fixed to only run while a session is actually active. Remaining: on-device jank/cold-start profiling needs a real connected device, not done this round.
- **Windows: can be simpler.** Basic transitions are fine here. Priority is low idle CPU/RAM over matching the mobile motion richness — trim timers, avoid unnecessary background work.

## 4. Polish (small, not a redesign)

- [x] **Onboarding/PIN-gate animation timing.** Caught live — the original staggered word-rise + delayed reveals made first launch feel slow. Cut all the artificial delays (title/paragraph/dots now appear immediately instead of ~2s of staggered waiting) on both the onboarding welcome screen and the PIN gate; kept the motion itself (logo draw-in, word rise) but tightened durations for a snappier, more fluid feel rather than removing it.
- [x] **Haptic feedback on Android.** Done, and refined after live feedback that raw `navigator.vibrate()` felt like a blunt buzz rather than a premium tap. Switched to native `View.performHapticFeedback()` via the `AndroidNative` JS bridge (`MainActivity.kt`) — the same OS-tuned constants system UI uses (`VIRTUAL_KEY` for taps, `CONFIRM`/`REJECT` for success/warn), not a manual vibration pattern. Wired into every `Pill`/`Chip`/`Switch` tap, each PIN digit entered, correct/wrong PIN, and marking something learned.
- [x] **Shorter, punchier AI coach message.** Done: cut the model's message cap from 140 to 90 characters and headline from 50 to 40, with an explicit "cut every word that isn't pulling weight" instruction. Deployed.
- [x] **Completion micro-interaction.** Scoped down to what's actually there: a distinct success haptic + the existing "Marked as learned" toast on completion. No new visual animation (e.g. confetti) — kept minimal rather than adding an untested effect under time pressure.

## 5. Companion / personalization

- [x] **Context-aware home message.** Done: coach now knows days since your last session/completion and what you recently finished, with explicit tone branches (warm re-entry after 4+ quiet days, lean in on a streak, simple first-message welcome, mention a growing backlog only when it's a real problem). Verified via test-coach.mjs against the real account. Still open: quiet mode during a declared break, which depends on streak-freeze below.
- [x] **Streak freeze / take a break mode.** Done: Settings → "Take a break" (Tomorrow/3 days/1 week/Until I resume presets, optional reason), stored in `profile.settings.break_*` (no schema migration, it's the existing jsonb column). `streak()` now takes a break-day set and treats those days as neutral — doesn't count toward the streak but doesn't reset it either, for both current and best-streak math. `replanNotifications` silences all nudges while on break. Home shows "On a break" + return date instead of the daily progress bar.

## 6. Notifications

- [x] **Quick actions in the notification itself.** Done: nudges now register a Skip/Snooze action type via `registerActionTypes`, the app's action handler reads the native `actionId` field to dispatch "Skip" (marks the item skipped) or "Snooze" (reschedules a fresh notification an hour out) without opening the app. Also fixed the underlying duplicate/stale-content bug this depended on: notification IDs are now deterministic per day+slot instead of colliding, and the replan trigger is persisted (`getPref`/`setPref`) instead of a `useRef` that reset on every reload.
- [x] **Weekly recap.** Done: Sunday 19:00 local notification summarizing the week's minutes/completions and current streak, computed client-side from the same stats helpers Home/Stats already use (no new AI call). Settings → Nudges has its own "Weekly recap" toggle, independent of the general notification switch — works even if regular nudges are off, and goes quiet during a declared break. Scoped down from the original "suggested focus for next week" idea to keep it a pure deterministic digest rather than another AI dependency.
